## 1. プロジェクト概要
- **目的**: 大阪リハビリテーション専門学校（OCR）の理学療法学科（PT）解剖学実習・小テスト対策用として、**授業配布レジュメ（PDF）に完全準拠**した高精度な問題バンク＆Webクイズアプリを構築する。
- **最終形態**: GitHub Pagesにデプロイ可能なスタンドアロンHTML/JSクイズアプリ（スマホ最適化、通学電車のスキマ学習対応）。
- **最重要要件**:
  1. **問題の完全網羅性（Coverage）**: 授業レジュメに書かれた筋（起始・停止・支配神経・髄節・作用・臨床コラム・注釈）を漏れなく出題化。
  2. **資料との1対1リンク（Traceability）**: 各問題の解説に「どのレジュメPDFの何ページ何行目か」を明記・参照可能にする。
- **対象試験範囲**:
  1. 前腕前面の筋
  2. 前腕後面の筋
  3. 手の筋（内在筋：母指球筋、小指球筋、中手筋）
  4. 体幹起始・上肢停止の筋（僧帽筋、菱形筋、前鋸筋、大胸筋、広背筋など）

- **補助ソース（Secondary）**:
  - `解剖学実習 筋学表前期.pdf`（記載内容のクロスチェック用）

## 3. 「ハーネス（Eval-Harness）」の評価指標（レジュメ特化型）
1. **網羅性ハーネス（Coverage Metric）**:
   - レジュメPDFから抽出されたエンティティ（筋名・起始停止・神経・髄節・作用・太字/赤字キーワード）が、生成問題に100%カバーされているかを自動検証。
2. **資料トレース整合性ハーネス（Traceability / Citation Check）**:
   - 全問に `source_pdf` と `page_number`、`quote_snippet`（レジュメ原文抜粋）が正しく紐付いているか。
3. **ファクト整合性ハーネス（Fact Correctness）**:
   - 正解・選択肢・解説がレジュメ原文と矛盾していないか。
4. **UI・実機表示ハーネス（Device & Geometric Quality）**:
   - GitHub Pagesで動作するHTMLクイズアプリにおいて、スマホ実機表示（390px幅など）で文字溢れ・レイアウト崩れがないかを検証。

## 4. プロジェクトロードマップ
- **フェーズ1（準備完了）**:
  - Googleドライブからの資料抽出 ＆ プロジェクトフォルダ作成
- **フェーズ2（マスターデータ構築）**:
  - 資料から筋学マスターJSON（各筋の起始・停止・神経・髄節・作用・臨床ポイント）を構造化
- **フェーズ3（ハーネスの実装）**:
  - `harness/eval_quiz.js`（またはPython）を作成し、問題生成の評価ルールを定義
- **フェーズ4（クイズジェネレータ & 問題バンク生成）**:
  - ハーネスの全テストをPassする問題セット（基礎〜国試・小テストレベル）を生成
- **フェーズ5（Webアプリ / UI実装 & ビジュアル検証）**:
  - スマホ最適化されたクイズWebアプリ（GitHub Pages公開可能、暗記カード＋4択テストモード）の構築
